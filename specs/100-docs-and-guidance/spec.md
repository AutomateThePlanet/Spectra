# Feature Specification: Docs and Guidance (Phase 6, Part 5)

**Feature Branch**: `100-docs-and-guidance`
**Created**: 2026-10-16
**Status**: Draft
**Input**: User description: "100-docs-and-guidance: Phase 6, the final spec of the doc-change → criteria → test
workflow plan. Documentation, agent guidance and the constitution catch up with specs 078–099. No behaviour change:
the only code change is help-text strings. Every other command output stays byte-identical (099's golden check; its
help-output files are updated deliberately, and only for help-text changes)." (Background, F1–F6, constraints and scope
as quoted in the request.)

## Context

Specs 059–099 changed how SPECTRA is used — generation, criteria extraction and the critic run in the user's own
session through skills; updates run through triage, relink, group edits and re-verification — but the documentation,
the agent guidance (CLAUDE.md, bundled skills) and the constitution still describe parts of the old product. A new
user who follows the README quick start types a command that no longer exists.

Facts (verified on `71b1bea`):
- **Removed commands in user docs.** `spectra ai generate` (removed in 059) appears as something to run in README.md
  (6 times, incl. the quick start) and in docs/usage.md, cli-reference.md, configuration.md, index.md,
  customization.md, document-index.md, skills-integration.md and claude-code-v2-migration.md. README.md,
  cli-reference.md, configuration.md, customization.md, execution-agents.md, getting-started.md,
  grounding-verification.md, testimize-integration.md and DEVELOPMENT.md mention `spectra auth`, providers or
  SPECTRA's MCP server in some form (each to be classified: removed-as-instruction vs. legitimate, e.g. the separate
  system-under-test MCP).
- **Two docs are also shipped content.** docs/usage.md and docs/customization.md are embedded in the CLI and written
  by `spectra init` as `USAGE.md` and `CUSTOMIZATION.md` (and refreshed by `update-skills` when unedited). Editing them
  changes what `init` writes; 099's golden `files.txt` captures `CUSTOMIZATION.md` today.
- **Removed command in runtime text.** `spectra ai analyze --extract-criteria` (removed in 069; extraction is the
  `spectra-criteria` skill) is still printed or written by: the init next-step hints, the two criteria files `init`
  writes (`_criteria_index.yaml` header, example criteria file), the coverage report's "no criteria" line, the
  generation and update prompt compilers' "no criteria" warnings, the dashboard's empty-coverage text, and the bundled
  `spectra-docs`, `spectra-help` and `spectra-generate` skills. `spectra ai generate` is still printed by `ai update`
  (two messages) and by the token pre-flight hint. The init hints also advertise "Create a Copilot Space … See
  docs/copilot-spaces-setup.md" (the doc does not exist). The bundled `spectra-quickstart` skill has a "Workflow 9:
  Execute Test Cases via MCP" heading. Run reports (Markdown and HTML) end with "Generated by Spectra MCP Server".
- **CLAUDE.md** (332 lines): its Commands section lists `spectra ai generate` and `ai analyze --extract-criteria` /
  `--skip-splitting`; Tech Stack names `Microsoft.Extensions.AI.Abstractions` (removed in 099); Active Technologies
  names the GitHub Copilot SDK; Project Structure lists deleted folders and classes; Recent Changes is ~250 lines of
  per-spec detail already held by CHANGELOG.md and specs/.
- **depends_on.** docs/test-format.md:66 documents `depends_on` as `string[]`; a test's dependency is a single test id
  — a list form does not parse (090 decision), and `spectra delete` warns about such files.
- **Help text.** `spectra config --help` gives `'source.dir'` and `'ai.defaultProvider'` as example keys (neither exists; the source folder key is `source.local_dir`). `spectra run`'s
  description says "(no MCP server required)".
- **Constitution 2.0.0**: Quality Gates still say "MCP tool contracts" (~line 109) and Code Review "new MCP tools"
  (~line 118). Principle III says output stays "minimal and structured"; the user's decision that the human summary is
  never suppressed in JSON mode (stdout = JSON only, summary on stderr) is not recorded. Principle IV's `--dry-run` gaps
  were closed by 090/097.
- **usage.md already has "Updating Test Cases After Doc Changes"** (≈ 140 lines, from triage onward); it does not
  start at "docs changed" / criteria, has no worked example, and one test pins its heading text.

## Decisions

Made while writing this spec (open to change at `/speckit.clarify`):

- **Scope widened to user-visible runtime text (user decision, 2026-10-16).** Besides help text, 100 fixes every
  user-visible string and bundled skill/agent text that names a removed command, option, key or document (the list in
  Context). These are text-only changes: no condition, exit code, JSON key or file set changes. Each affected golden
  file is re-captured and its diff reviewed line by line; only the named strings may differ.
- **Embedded docs are expected golden changes.** Because `USAGE.md` / `CUSTOMIZATION.md` are init output, F1/F2 edits
  to docs/usage.md and docs/customization.md change `init`'s written files. That is intended: the user's workspace
  should get the corrected guide. `update-skills` refreshes unedited copies and never overwrites edited ones (096 rule,
  unchanged).
- **Replacement wording for removed commands.** `spectra ai generate` → "ask your assistant to generate tests (the
  `spectra-generate` skill)"; `spectra ai analyze --extract-criteria` → "the `spectra-criteria` skill"; a CLI-only
  context (CI, no assistant) names the seam commands it actually runs. The Copilot Spaces hint lines are removed. The
  report footer becomes "Generated by SPECTRA".
- **Historical files.** The FR-003 list (research R2) may mention removed commands only as history; the migration and
  cost guides get a clear "removed in …" marker where they show a removed command, and PROJECT-KNOWLEDGE.md /
  architecture-v5.md a "historical document" banner. These form the file part of the guard's allow-list.
- **The new guide replaces the old section.** "When documentation changes" replaces "Updating Test Cases After Doc
  Changes" in usage.md (content kept where still right, restructured into the 10 steps, plus the worked example); the
  test that pins the old heading is updated to the new one.
- **Version for the constitution: 2.1.0 (MINOR).** Clauses are clarified and one rule added to Principle III; no
  principle is removed or redefined.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — A new user follows the docs and every command works (Priority: P1)

A new user reads README.md and the docs, then runs what they say. Every command, option and key they are told to run
or set exists; removed ones appear only in the marked historical files, as history.

**Why this priority**: today the quick start fails at its first generation step. This is the defect users hit first.

**Independent Test**: scan README.md and every user-facing doc for the removed commands/keys (guard test), and check
every `spectra …` command line in README's quick start against the CLI's command tree.

**Acceptance Scenarios**:

1. **Given** README.md, **When** the user follows the quick start, **Then** generation is described as asking the
   assistant (the `spectra-generate` skill), and every `spectra …` line in it is a command the CLI accepts.
2. **Given** any user-facing doc, **When** it is scanned for `spectra ai generate`, `spectra auth`, `ai.providers`,
   the in-process critic keys, `--extract-criteria`, `--skip-splitting` or SPECTRA's MCP server, **Then** none appears,
   except in allow-listed historical files.
3. **Given** a historical file that shows a removed command, **When** the user reads it, **Then** the command is
   marked as removed (with the spec/version).

### User Story 2 — One guide for "my docs changed" (Priority: P1)

A user whose product documentation changed wants to bring the tests up to date. One section in usage.md ("When
documentation changes"), linked from README.md and docs/index.md, walks the whole flow with one worked example.

**Why this priority**: this is the original goal of the 078–099 plan; without a guide the flow is only discoverable by
reading ten spec folders.

**Independent Test**: read the section; a guard test checks every `spectra …` line in it against the command tree.

**Acceptance Scenarios**:

1. **Given** the section, **When** a user reads it, **Then** it covers, in order: docs changed; criteria
   (`spectra-criteria`: moves, retires, re-extraction); update-triage buckets; relink; REMOVED review; group edits
   through `spectra-update` (subagents); `unchanged_pending`; re-verification by the critic; update-ack; what is
   committed vs. scratch.
2. **Given** the worked example, **When** each command it shows is run in an init-created workspace (or checked
   against the command tree), **Then** each exists with the options shown.
3. **Given** README.md and docs/index.md, **When** the user looks for doc-change guidance, **Then** both link to the
   section.

### User Story 3 — The CLI never points to a removed command (Priority: P2)

A user running SPECTRA sees hints, warnings, generated file comments, help text and report footers. None of them tells
the user to run a command that no longer exists or links a missing doc.

**Why this priority**: same defect as Story 1, met inside the product rather than the docs.

**Independent Test**: the golden check (099) passes after re-capture, and the reviewed diff contains only the listed
string changes; a guard scans `src/` user-visible strings and bundled content for the removed commands.

**Acceptance Scenarios**:

1. **Given** `spectra config --help`, **When** shown, **Then** the example keys exist in the config (e.g.
   `source.local_dir`, `tests.dir`).
2. **Given** `spectra init` in an empty folder, **When** it finishes, **Then** its hints and the criteria files it
   writes name the `spectra-criteria` skill, not `--extract-criteria`, and no Copilot Spaces line is printed.
3. **Given** `ai update` with no tests, or a token pre-flight refusal, **When** the message is printed, **Then** it
   names the `spectra-generate` skill.
4. **Given** a finalized run, **When** the Markdown or HTML report is written, **Then** its footer does not mention an
   MCP server.
5. **Given** the golden check, **When** re-run after re-capture, **Then** every other byte of every output is unchanged
   (diff reviewed and recorded).

### User Story 4 — Agents get current guidance (Priority: P2)

A Claude Code session in this repository loads CLAUDE.md. It describes the product as it is now: tech stack, existing
folders, real commands, code style, execution note, and one or two lines per recent spec pointing to CHANGELOG.md and
specs/NNN.

**Why this priority**: stale guidance makes agents look for removed commands and deleted folders, costing time and
causing wrong edits.

**Independent Test**: guard test — every command line in CLAUDE.md's Commands block exists in the command tree, and
every folder in Project Structure exists; CLAUDE.md is ≤ 150 lines.

**Acceptance Scenarios**:

1. **Given** CLAUDE.md, **When** its Commands block is checked, **Then** every command and option exists.
2. **Given** CLAUDE.md, **When** its Project Structure is checked, **Then** every folder named exists.
3. **Given** CLAUDE.md, **When** counted, **Then** it has ≤ 150 lines and no removed dependency or command.

### User Story 5 — The constitution states the rules the code follows (Priority: P3)

A contributor reads the constitution. It says CLI command contracts (JSON output and exit codes), not MCP tools; it
states the human-summary rule for JSON mode; and Principle IV reflects that the batch ingest commands support
`--dry-run`.

**Why this priority**: governance text; no user sees it, but reviews are judged against it.

**Independent Test**: read the constitution diff and its Sync Impact Report.

**Acceptance Scenarios**:

1. **Given** the constitution, **When** read, **Then** it is version 2.1.0 with a Sync Impact Report listing the
   changed clauses and the checked templates.
2. **Given** Principle III, **When** read, **Then** it says: in JSON mode stdout is only the JSON document; the human
   summary is never suppressed and goes to stderr.
3. **Given** Principle IV, **When** read, **Then** it notes that the batch ingest commands support `--dry-run`
   (090/097) and that `--no-review` is a global option with no effect where nothing prompts.

### User Story 6 — depends_on documented as it is (Priority: P3)

A test author reads docs/test-format.md and learns that `depends_on` is one test id; a list makes the test unparseable
and `spectra delete` warns about such files.

**Independent Test**: read the field table and any example; check that no doc shows a list form as valid.

**Acceptance Scenarios**:

1. **Given** docs/test-format.md, **When** read, **Then** `depends_on` is a single test id (string), with a note that
   lists are not supported.

### Edge Cases

- A doc mentions the separate system-under-test MCP (BELLATRIX/Nova) or the Azure DevOps MCP: legitimate, not a removed
  concept — the guard matches SPECTRA's own MCP server, not every "MCP".
- A removed command appears inside a bundled skill as an explicit "there is no `spectra ai generate`" warning to the
  agent: legitimate; the guard allow-lists these exact negative statements.
- `ai update` (legacy) is still a real command: docs may describe it as legacy, never as the recommended update path.
- A user's edited `USAGE.md` / `CUSTOMIZATION.md`: `update-skills` keeps it (096 rule) — the corrected text reaches
  only unedited copies; the guide says how to reset.
- A golden diff shows a change outside the listed strings: the change is wrong and is reverted, not re-captured.
- The worked example's commands must run offline without a model (only compile/ingest/triage steps are shown as
  commands; model turns are described, not scripted).

## Requirements *(mandatory)*

### Functional Requirements

**F1 — Docs describe the product as it is**

- **FR-001**: README.md, CONTRIBUTING.md and every user-facing doc under docs/ MUST describe generation, criteria extraction, update
  and verification through the skills (`spectra-generate`, `spectra-criteria`, `spectra-update`) and the real commands
  (compile-*/ingest-* seam, update-triage, update-ack, relink-sources, source-baseline, audit-grounding,
  ingest-verdict / ingest-grounding `--ids`, compile-prompt `--batch`, delete / suite delete, …).
- **FR-002**: No user-facing doc MAY present a removed command, option or key as something to run or set:
  `spectra ai generate`, `spectra auth`, `ai.providers`, the in-process critic keys (`ai.critic.provider`,
  `api_key_env`, `base_url`, `enabled`, `timeout_seconds`, `max_concurrent`), `ai analyze --extract-criteria`,
  `--skip-splitting`, SPECTRA's MCP server.
- **FR-003**: Historical files (explicit allow-list = research R2: docs/claude-code-v2-migration.md,
  docs/ai-models-cost-guide.md, docs/migration-040.md, docs/architecture/ARCHITECTURE-v2.md, architecture-v5.md,
  PROJECT-KNOWLEDGE.md, the root `FINDINGS-*.md` / `INVESTIGATION-*.md` / `VERIFICATION-*.md` files, CHANGELOG.md,
  specs/**, docs/specs/**, docs/investigation/**, docs/analysis/**) MAY mention them only as history; where a
  historical user guide shows a removed command, it MUST be marked as removed. PROJECT-KNOWLEDGE.md and
  architecture-v5.md, which read as current guides, MUST carry a "historical document" banner at the top.
- **FR-004**: A guard test MUST fail when a user-facing doc mentions a removed command/key outside the allow-list. The
  guard's allow-list is: the named historical files (FR-003), an explicit list of removal markers (a paragraph that says
  the command/key was removed, per research R2), and the named legitimate MCPs (the separate BELLATRIX/Nova SUT driver
  and Azure DevOps bug-log MCPs). All three lists MUST be explicit in the test.
- **FR-004a**: A guard test MUST fail when a command in the CLI's command tree is not documented in
  docs/cli-reference.md: a command counts as documented when its full path (`spectra <group> <name>`, or `<group> <name>` for a subcommand) appears in a heading or a code span/block of docs/cli-reference.md — not as a bare word. Missing on `71b1bea` and added: `ai init-seam-progress`,
  `config add-automation-dir`, `config remove-automation-dir`, `config list-automation-dirs`, `run list-active`.

**F2 — One guide for the original goal**

- **FR-005**: docs/usage.md MUST contain a section "When documentation changes" covering, in order: docs changed;
  criteria (`spectra-criteria`: moves, retires, re-extraction); update-triage buckets; relink; REMOVED review; group
  edits through `spectra-update` (subagents); `unchanged_pending`; re-verification by the critic; update-ack; what is
  committed vs. scratch.
- **FR-006**: The section MUST contain one worked example; every command and skill step it names MUST exist (every
  skill and agent name in the section is a bundled skill or agent). It MUST say how to refresh an edited `USAGE.md` /
  `CUSTOMIZATION.md` (delete it and run `spectra update-skills`) and an edited prompt template (`spectra prompts reset
  <id>`).
- **FR-007**: README.md and docs/index.md MUST link to the section.
- **FR-008**: A guard test MUST check every `spectra …` line in that section against the real command tree (command
  path and options).

**F3 — depends_on**

- **FR-009**: docs/test-format.md MUST document `depends_on` as a single test id (scalar), state that list forms are
  not supported and make the test unparseable, and that `spectra delete` warns about them.

**F4 — Help and runtime text**

- **FR-010**: `spectra config`'s key example MUST use keys that exist (e.g. `source.local_dir`, `tests.dir`).
- **FR-011**: Every command and option description MUST be free of removed concepts (Copilot, providers, SPECTRA's MCP
  server, `ai generate`); only the text changes. The sweep also marks `spectra ai update` as legacy in its help, pointing
  to `update-triage`.
- **FR-012**: Every user-visible runtime string and bundled skill/agent/template text that names a removed command,
  option, key or missing document (list in Context) MUST be corrected; text only — no condition, exit code, JSON key,
  JSON value type or written-file set changes.
- **FR-013**: The 099 golden files MUST be re-captured only for the changed strings (help, init-written files incl.
  `CUSTOMIZATION.md` and its manifest hash, any other affected step); the diff MUST be reviewed and recorded, and MUST
  contain no other change. (`USAGE.md` is not in the golden run — it uses `init --skip-skills`; its embedded content is
  covered by `ProfileFormatLoaderTests` and the doc guards.)

**F5 — CLAUDE.md**

- **FR-014**: CLAUDE.md MUST be rewritten to the current state: tech stack, project structure (existing folders only),
  the real command list (matching the CLI's help), code style, execution note. AGENTS.md MUST point to CLAUDE.md and
  describe only the current projects, with no command list of its own (none to drift).
- **FR-015**: Recent Changes MUST be one or two lines per spec, pointing to CHANGELOG.md and specs/NNN. Rows cover specs
  078–100; the 044–077 history stays in CHANGELOG.md only.
- **FR-016**: CLAUDE.md MUST be ≤ 150 lines.
- **FR-017**: A guard test MUST check that every command line in CLAUDE.md's Commands block exists in the command tree
  and every folder in Project Structure exists.

**F6 — Constitution 2.1.0**

- **FR-018**: Development Workflow › Test-Required Discipline (~line 109): "MCP tool contracts" → "CLI command contracts
  (JSON output and exit codes)"; Code Review (~line 118): "new MCP tools" → "new CLI commands"; Governance: "Runtime
  development guidance is in `AGENTS.md`" → `CLAUDE.md` (AGENTS.md points to it).
- **FR-019**: Principle III MUST state: in JSON mode stdout is only the JSON document; the human summary is never
  suppressed and goes to stderr, so the user always sees what happened.
- **FR-020**: Principle IV MUST note that the batch ingest commands support `--dry-run` (090/097) and that `--no-review`
  is a global option with no effect where nothing prompts. Its clause "The AI agent MUST never write to the filesystem
  directly — all output goes through validated tool handlers" is replaced by: "The AI agent never writes tests, criteria, indexes, baselines or grounding directly. It writes only staging inputs under `.spectra/` (e.g. `.spectra/updates|repairs/<suite>/*.json`, `.spectra/generated.json`, `.spectra/analysis.json`, `.spectra/criteria.json`, critic verdict files) that a validated CLI ingest command reads; every persisted artefact is written by a CLI command." The Sync Impact Report
  records this as a clarification of existing behaviour (since 077/088), not a change.
- **FR-021**: The constitution MUST be 2.1.0 with a Sync Impact Report at the top; dependent templates (.specify/
  templates/*) checked and listed.

**Constraints**

- **FR-022**: No behaviour change beyond the text changes above; the golden check proves it.
- **FR-023**: The full test suite stays green with 0 build warnings.
- **FR-024**: CHANGELOG.md gains the 100 entry and a short "Highlights" summary at the top of the unreleased 2.6.0
  section covering 078–100 for users.

### Key Entities

- **Removed-concept list**: the commands, options, keys and names that no longer exist, with the spec that removed
  each — shared by the doc guard, the source-string guard and the reviewer.
- **Allow-list**: the historical files, the removal-marker list and the legitimate-MCP names (FR-004) under which a
  removed concept may be mentioned.
- **Command tree**: the CLI's real commands and options as the parser defines them — the reference for every
  "command exists" guard.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 0 mentions of a removed command/key as something to run or set across README.md and all non-historical
  docs (guard test).
- **SC-002**: 100% of `spectra …` lines in the README quick start, the "When documentation changes" section and
  CLAUDE.md's Commands block resolve in the command tree, and every command in the command tree is documented in
  docs/cli-reference.md (FR-004a rule) (guard tests).
- **SC-003**: CLAUDE.md ≤ 150 lines (from 332), every listed folder exists.
- **SC-004**: The golden check passes; the re-capture diff contains only the strings listed in Context (reviewed, 0
  unexplained lines).
- **SC-005**: 0 user-visible strings in `src/` (outside allow-listed negative statements) name a removed command,
  option or missing doc.
- **SC-006**: Full suite green, 0 build warnings.
- **SC-007**: A user can go from "my docs changed" to updated, re-verified, acknowledged tests by following one section
  only.

## Assumptions

- "User-facing docs" = README.md, CONTRIBUTING.md, AGENTS.md and docs/*.md plus docs/architecture/** (except
  ARCHITECTURE-v2.md, which is history) and docs/deployment/**, minus the historical allow-list; `.claude/` and `.specify/` are agent/tooling content (CLAUDE.md and the constitution are handled by F5/F6).
- The `spectra-quickstart` "Execute Test Cases via MCP" heading is retitled; the separate SUT-driver MCP mentions stay.
- The golden check covers help, init and the captured steps only; strings in paths it does not capture (ai update
  messages, report footer, pre-flight hint) are checked by the source-string guard and existing tests.
- Changing bundled skill text changes their hashes; `update-skills` refreshes unedited installed copies — normal and
  intended.

## Out of Scope

- The ImageSharp upgrade (a later step).
- `depends_on` list support.
- Any new feature, option or JSON field; renaming the cosmetic `Spectra.MCP.*` namespaces; spec-number references in
  help text ("Spec 071") unless they name a removed concept.
